1. The big picture

PhishGuard reads an email and tells you how suspicious it is. It gives a score from 0 to 100 plus a list of findings — each finding is one reason the email looks phishy, written in plain English.

There are two editions of the same app, and they share the exact same brain:

Server editionBrowser edition
WhereRoot folder (app.py + analyzer.py)docs/ folder (GitHub Pages)
RunsPython on a computer or server100% inside your web browser
URLhttp://127.0.0.1:8000 (localhost)https://bpoit.github.io/VW-Hackathon-phishguard/
Email dataSent to the app, then thrown away (never saved)Never leaves your computer at all
Used forLocal demo + judging the repoShared link anyone can open
💡 Why two editions? Judges clone the repo and run the server edition. The browser edition is the link you put on your slide — it works even if your laptop or internet fails, because there's no server to break.

3a. The Report object (what comes back)

FieldMeans
score0–100. Higher = more phishy.
verdictlikely_safe, suspicious, or likely_phishing.
findingsList of {severity, title, detail}. This is the "why".
urlsEvery link found in the email.
countsHow many high/medium/low/info findings there are.
🔎 Jargon — "heuristic": a rule of thumb. Not 100% proof, but a strong smell. Example: "emails that say URGENT and ask for your password are usually fake." Our app uses dozens of these rules.

3b. URL checks — _check_urls()

Every link in the email gets inspected:

FindingSeverityWhat it catches
URL uses a raw IP addresshighhttp://192.168.1.55/login — real sites use domain names, not bare IP numbers.
Internationalised (punycode) domainhighDomains with disguise characters (foreign alphabets or xn-- codes) that imitate big brands.
Misleading '@' in URLhighhttp://paypal.com@evil.com — the browser actually goes to evil.com.
Brand lookalike domainhighpaypa1.com, app1e-id-secure.com (those are number 1s, not letters).
Deeply nested subdomainsmediumlogin.paypal.secure.verify.example.com — 5+ parts hides the real owner (it's example.com).
Unusual host formatmediumDomain that's just numbers or hex code instead of a name.
Unencrypted http:// linklowNot HTTPS. Legit login pages always use HTTPS.
🔎 Jargon — "punycode": the browser's way of showing foreign-character domains in plain ASCII. Bad guys use it because аpple.com (Cyrillic "а") looks identical to apple.com to your eyes.

3c. Sender checks — _check_sender()

The From line is split into a display name (the pretty part, like "Apple Support") and the real address (verify@app1e-id-secure.com).

FindingSeverityExample that triggers it
Display name / sender domain mismatchhighDisplay name says Netflix but the address is @randomhost.net.
Lookalike sender domainhighAddress uses paypa1 / g00gle / arnazon tricks (see built-in list below).
Free mail sendermedium"Apple" emailing you from @gmail.com. Real companies own their own mail servers.
No sender providedinfoThe From field was empty (only noted if there's other content to check).

Two small data tables power this:

# Homoglyph map — "written wrong on purpose"
LOOKALIKE_TOKENS = {
    "paypa1": "paypal",  "paypai": "paypal",  "micros*f": "microsoft",
    "app1e":  "apple",   "g00gle": "google",  "arnazon": "amazon",
}

# Big brands attackers love to pretend to be
FINANCIAL_SENDERS = paypal | apple | microsoft | google | amazon
                    | netflix | bank | coinbase | irs

# Free email providers (legit companies don't send notices from these)
FREE_MAIL_DOMAINS = gmail, yahoo, hotmail, outlook, aol,
                    proton.me, protonmail, icloud, mail.com

3d. Wording checks — _check_body()

Looks at the subject + body text for classic scam language:

FindingSeverityPhrases that trigger it
Urgency pressuremedium"urgent", "act now", "within 24 hours"
Threat of account actionmedium"suspend", "terminate", "restricted", "closure"
Verification luremedium"verify your account", "confirm your identity"
Fake security alertmedium"unusual login activity", "failed sign-in"
Advance-fee / prize baitmedium"you won", "congratulations", "prize", "wire transfer"
Credential harvesting requestmedium"enter your password", "provide your credit card"
Requests sensitive informationhighAsks you to submit password/SSN/card via email. Never do this.
Link text does not match destinationhighBlue text says "Click here to reset your Apple ID" but the link really goes to example.com. (Only works if you paste the raw HTML.)
Suspicious attachment typemediumMentions .exe .zip .js .scr .vbs .iso .lnk files.
Generic greetinglow"Dear Customer" instead of your real name = mass mailing.

3e. Reading a whole raw email

If you paste an entire email (headers + body), analyze() splits it itself:

From: Apple Support    ← header lines
Subject: Urgent: account will be suspended
                                                    ← blank line = separator
Dear Customer, ...                                   ← body starts here

The rule is simple: find the first blank line. Everything above is headers, everything below is the body. It pulls out just From: and : — the other headers are ignored on purpose.

4. How the score and verdict work

Each finding is worth points. Add them up. Clamp to 0–100 (so it never goes over or under).

SeverityPoints
high25
medium12
low5
info0 (just a note)
Final scoreVerdictWhat it means
60 – 100likely_phishingMultiple strong red flags. Don't click, don't reply.
30 – 59suspiciousSome warning signs. Check with the real company using a number you already have.
0 – 29likely_safeNothing major found. Still stay careful.
💡 Example: the built-in sample trips 3 high + 4 medium + 2 low findings.
(3×25) + (4×12) + (2×5) = 75 + 48 + 10 = 133 → clamped to 100 → likely_phishing.

Findings are always shown worst-first (high → medium → low → info) so the scariest reasons hit your eyes first.

🔎 Jargon — "clamp": force a number to stay inside a range. 133 becomes 100, -5 becomes 0. This stops the score from becoming nonsense when many findings stack up.

5. The server: app.py

This file is just a thin wrapper. It does three things: receive, guard, respond.

Route (URL)Job
GET /Show the main page (form + report area).
POST /analyzeTake the email → run the brain → send back the report.
GET /healthzHealth check. Returns {"status":"ok"} so tools (and judges!) can see the app is alive.

The guards (security decisions worth mentioning to judges)

GuardCodeWhy
No debug modedebug=FalseDebug mode has a built-in console that lets hackers run code on your server. Never public with it on.
Size limitMAX_PASTE_CHARS = 50_00050,000 characters max. Stops someone pasting a huge file to eat all the memory. Over limit → HTTP 413.
Empty input rejected400No email given? Nicely refused with a friendly message.
Nothing savedno open(), no databaseThe email is held in a variable for one request, then Python throws it away. It's never written to disk or logged.
Reads two input stylesJSON or formThe AJAX version sends JSON; the plain HTML form (no-JS fallback) sends form data. Both work. Direct file upload (raw_file) is also accepted and read in memory.
# The flow inside POST /analyze, simplified:
1. Read input       (JSON body, form fields, or uploaded file)
2. Size guard       (> 50,000 chars?  → 413 "too large")
3. Empty guard      (nothing to check? → 400 "paste an email")
4. report = analyze(...)          ← the brain
5. Return JSON (for AJAX) or re-render the page (for plain form)

6. The front-end (static/app.js + templates/index.html)

FeatureHow it works
📊 Score ringA circle that fills up like a gauge. CSS does the drawing (conic-gradient + a --pct variable); JavaScript animates the number from 0 → score over 0.9 seconds with an ease-out curve (fast start, gentle stop — feels nicer than a linear jump).
🧪 "Load a phishing sample"Fills the three fields with a realistic scam (brand spoof, raw-IP link, urgency words, credential ask) so you can demo in one click.
📄 File uploadFileReader reads the .eml/.txt file inside the browser (memory only — never uploaded anywhere), splits headers from body with parseEmail(), fills the boxes, and auto-analyzes.
🔐 Encoded header decodingparseEmail() understands base64 and quoted-printable encoded subjects (the =?UTF-8?B?...?= gibberish you see in raw emails) so the real subject shows up.
⚡ AJAX submitThe form posts with fetch() so the page doesn't fully reload. If anything fails, it falls back to a normal form submit — the page still works without JavaScript.
🛡️ XSS safetyEvery value shown in the report goes through esc() (sets textContent, reads back innerHTML) so a malicious email can't inject scripts into the page while you're inspecting it. Ironic to get hacked by the phish you're examining!

9. How to run it

Server edition (your laptop — this is the live demo)

git clone https://github.com/bclarketech/VW-Hackathon-phishguard.git
cd VW-Hackathon-phishguard

python -m venv .venv                 # one-time: virtual environment
.\.venv\Scripts\Activate.ps1         # Windows activate (use: source .venv/bin/activate on Mac/Linux)
pip install -r requirements.txt      # one-time: install packages

python app.py                        # ← run this. Opens http://127.0.0.1:8000

Production-style run (what you'd say when judges ask "how would you deploy this?"):

gunicorn -w 2 -b 127.0.0.1:8000 app:app
# -w 2 = two worker processes. 127.0.0.1 = only this computer can reach it.
⚠️ gunicorn does not work on Windows — it's Unix-only. On Windows use python app.py (which runs with debug=False — still safe). Mention gunicorn as the Linux/production path in your presentation, but run the demo with python app.py.

Browser edition (GitHub Pages — no install at all)

Just open: https://bpoit.github.io/VW-Hackathon-phishguard/

Run the tests

python -m unittest discover -s tests -v    # 18 tests
node /tmp/test-engine.js                   # JS engine sanity check (browser edition)

10. Jargon glossary

WordPlain meaning
HeuristicA rule of thumb. Strong evidence, not proof.
SeverityHow dangerous a finding is: high / medium / low / info.
Punycode / homoglyphCharacters that look like letters but aren't (number 1 for l, Cyrillic а for a).
ClampForce a number to stay inside a set range (0–100).
FlaskA small Python web framework — the glue between the browser and our brain.
GunicornA production web server for Flask. Safer than the built-in dev server. Not on Windows.
RouteA URL the server answers, like /analyze.
HTTP status codesNumbers that say how a request went: 200 = OK, 400 = bad request, 413 = too big.
JSONA plain-text data format ({"score": 100}) that programs exchange.
AJAX / fetchSending data behind the scenes so the page doesn't reload.
XSSCross-Site Scripting — an attacker hiding code inside content you view. We block it with esc().
FileReaderA browser tool that reads a file you pick — in browser memory, no upload.
GitHub PagesFree website hosting straight from a repo's docs/ folder.
Debug modeA developer convenience that exposes a dangerous console. Always off in production.
Unit testA tiny automatic check that one piece of code does its job.
